这套方法能用在哪

  • 能预测：新问题提交时，和已有问题逐一配对打分，概率高的直接提示“可能已有人问过”。
  • 同类问题：FAQ 匹配、客服工单去重、专利/论文查重、商品标题归一、搜索里的“查询-文档”相关性。
  • 可迁移的套路：文本对 → 手工相似度特征（重叠、加权重叠、长度差）→ 树模型；评估指标看概率时，训练集的类别比例要对齐测试集。

方法清单

05课堂讨论

  1. “How do I learn Python?” 和 “How can I learn Python quickly?” 共享词比例很高；“Is Python faster than Java?” 和 “Is Java faster than Python?” 共享词比例是 1 但意思相反。词袋类特征的盲区在哪？
  2. 作者用排行榜分数反推测试集正例比例，然后据此重平衡训练集。这在真实业务里对应什么？如果线上分布会变，该怎么办？
  3. 作者在第 22 格写了 eps = 5000，但 get_weight 用的是默认参数 eps=10000。这个变量真的生效了吗？这类 bug 怎么避免？
  4. 按第 29 格的代码逻辑算一算，最后正例比例真的是 16.5% 吗？（可用实验 B 验证）
  5. 先用重平衡后的数据再 train_test_split 切验证集，同一个负例的多个复制品可能同时出现在训练和验证里。这会让验证分数偏乐观还是偏悲观？
