01一分钟看懂

数据是什么

5 万条英文电影评论

IMDB 影评数据集，每条是一段长短不一的影评原文和情感标签 positive / negative，好评、差评各 2.5 万条（来自数据集说明）。出处

要预测什么

这条影评是好评还是差评

输出“好评”的概率，大于 0.5 判为 positive。和词袋模型不同，这里让模型按顺序读词，有机会理解 “not good” 这类依赖词序的表达。

用了什么方法

词表编码 → 嵌入 → 两层 LSTM

只保留最常见的 1000 个词并编号；每条影评左侧补 0 到 500 个位置；64 维词嵌入，两层 256 单元的 LSTM，取最后一步的输出接 sigmoid。

做到了什么

一条完整的 PyTorch 文本分类流程

从切分、分词、填充、批处理到训练循环、梯度裁剪、保存最优模型、单条推理都写全了。作者在末尾提出了改进方向：调参、用 GloVe 预训练词向量、双向 LSTM。出处

这套方法能用在哪

  • 能预测：输入一段评论文字，输出“正面”的概率，可以汇总成某部电影、某件商品的口碑走势。
  • 同类问题：电商评论、App 商店评分、微博舆情、客服对话满意度、股评情绪。
  • 可迁移的套路：任何“变长序列 → 一个标签”的问题都能套用：词表编码 → 填充成定长 → 嵌入 → RNN/LSTM → 取最后状态分类。

方法清单

  • 预处理：去非字母字符和数字、去停用词、取前 1000 高频词 第 10 格
  • 填充：左侧补 0，长度 500 第 18 格
  • 批处理：TensorDataset + DataLoader，batch 50 第 21 格
  • 模型：Embedding(1001, 64) → LSTM(64→256, 2 层) → Dropout → Linear → Sigmoid 第 25 格 第 26 格
  • 训练：BCELoss + Adam(lr=0.001)，5 轮，梯度裁剪 5，按验证损失保存最优 第 28 格 第 29 格
  • 推理：predict_text 单条预测 第 32 格

05课堂讨论

  1. 作者去掉了停用词，而 “not”、“no” 都在 NLTK 停用词表里。这对情感分析有什么后果？“not good” 进入模型时还剩下什么？
  2. 为什么要在左边补 0，而不是右边？如果改成右边补 0，又只取最后一个时间步的输出，会发生什么？
  3. 词表只留 1000 个词，其余全部丢掉。一条影评平均剩约 69 个词，原文却长得多。丢掉的信息值得吗？怎么权衡词表大小？
  4. embedding_dim=64 而词表是 1001：嵌入层有多少个参数？和独热编码相比省了多少？
  5. 梯度裁剪解决的是什么问题？为什么 RNN 特别容易梯度爆炸？
  6. 和 SMS 案例里的 TF-IDF + 朴素贝叶斯相比，LSTM 多付出了什么代价（数据量、算力、可解释性），换来了什么？
