七个模型的 ROC AUC 打印在运行输出里，源码不带输出，作者文字也没写，这里不列分数。而且下方“评估陷阱”说明，第 57 格和第 88 格的写法本身会让 AUC 偏离真实水平，读原作者的数字时要留意。

评估代码里的三个陷阱

  • AUC 用 model.predict() 的 0/1 标签计算，而不是 predict_proba 的概率，ROC 曲线只剩一个拐点 第 57 格
  • 逻辑回归、SVM 在标准化数据上训练，第 57、88 格却在未标准化的 X 上打分 第 88 格
  • PR 曲线、ROC 曲线同样基于 0/1 预测，曲线退化成折线 第 56 格

这套方法能用在哪

  • 能预测：给每位员工一个离职风险分，HR 可据此优先安排面谈、调岗、调薪或改善加班。
  • 同类问题：会员流失、学生辍学预警、销售人员流失、司机/骑手流失。
  • 可迁移的套路：删掉常数列和 ID 列 → 分组直方图看差异 → 独热编码（drop_first 防共线）→ 分层切分 → 多模型 + 网格搜索 → 用概率算 AUC，画精确率/召回率随阈值变化的曲线。
  • 伦理提醒：“单身、男性更容易走”这类结论不能用来做歧视性的人事决定；模型更适合发现可改进的因素（加班、薪资、晋升）。

方法清单

  • 删除无信息列 第 10 格
  • 独热编码 + 去重 第 42 格、第 43 格
  • 分层切分 7:3 + 标准化 第 48 格
  • L1 逻辑回归 第 55 格
  • 随机森林网格搜索（5 折，AUC） 第 60 格
  • SVM 网格搜索（线性 / RBF） 第 66 格
  • XGBoost 第 71 格、LightGBM 第 76 格、CatBoost 第 80 格、AdaBoost 第 84 格

05课堂讨论

  1. 为什么用 0/1 预测值算出来的 AUC，通常比用概率算的低？在实验里比较两者，并说说什么时候差得最多。
  2. 一个在标准化数据上训练的逻辑回归，拿未标准化的数据去预测，会发生什么？你能想到用 Pipeline 怎样从结构上避免这个错误吗？
  3. 月薪和职级高度相关。L1 正则在两个高度相关的特征之间会怎么“取舍”？这对解释“谁影响离职”有什么风险？
  4. 随机森林网格有 648 种参数组合，5 折就是 3240 次训练。只有 1000 来条数据时，这么大的搜索可能带来什么问题？
  5. 数据是 IBM 虚构的。用虚构数据得出的“加班的人更容易走”，能直接搬到你所在的单位吗？
