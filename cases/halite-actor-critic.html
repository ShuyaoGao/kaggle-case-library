结论：船能采矿、变船坞、没船时再造船，表现“挺聪明”；希望以后能找最近的船坞、控制多艘船第 38 格

训练过程打印的 running reward 和对局回放都在运行输出里，Kaggle 下载的源码不带，作者文字里也没给数字，所以这里不列分数。“表现聪明”是作者看回放的主观判断，没有和规则机器人做定量比较。

这套方法能用在哪

  • 能做什么：动作有限、需要连续做很多步决策的任务，让网络同时学“怎么做”（演员）和“做得怎么样”（评论家）。
  • 同类问题：即时战略游戏、物流车队调度、无人机巡检路径、扫地机器人覆盖。
  • 可迁移的教训：先写一个规则机器人当基线；网络的输入要包含做决定所需的信息（比如船在哪）；奖励要奖励“变化”而不是“存量”；不要用 try/except: pass 吞掉错误。

05课堂讨论

  1. 网络的输入只有“每个格子剩多少矿”，没有“船在哪”“船上装了多少”。网络能学会“往东开”还是“往西开”吗？
  2. 奖励是“当前已存矿量 / 5000”，每一步都给一次。存了 1000 之后什么都不做，每步仍能拿 0.2。这种奖励鼓励的是什么？实验 C 里换一种奖励试试。
  3. 第 33 格的 update_L1() 里写了 ship_+=1，却没有声明 global ship_，Python 会报错；而外面又包了 try: … except: pass。结果会怎样？
  4. 网络选的方向，只有在“收集状态且脚下矿少于 100”时才会被执行，其他时候都是规则在开船。那网络学到的东西还剩多少作用？
  5. 作者凭看回放判断“船很聪明”。你会设计什么实验，来证明 Actor-Critic 版比第 20 格的规则机器人更好（或更差）？
