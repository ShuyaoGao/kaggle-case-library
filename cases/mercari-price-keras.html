第 16 格验证集 RMSLE 打印在运行输出里，源码不带，这里不列。另外该格把预测还原成价格时写成了 np.exp(...) + 1，而目标是 log(price + 1)，正确还原应为 np.exp(...) − 1（第 17 格做对了），所以第 16 格的验证分数会略有偏差。

这套方法能用在哪

  • 能预测：卖家上传商品标题和描述后，自动给出建议售价；平台也能据此发现标价明显异常的商品。
  • 同类问题：闲鱼、eBay 等二手平台定价，房源描述 → 租金，招聘启事 → 薪资，酒店评论 + 设施 → 房价。凡是“文本 + 表格”一起决定一个数值的问题都适用。
  • 可迁移的套路：类别列用 LabelEncoder + Embedding；文本列用 Tokenizer + pad_sequences + Embedding + RNN；多路输入拼接后接全连接；目标取对数再缩放；用 Keras 函数式 API 搭多输入模型。
  • 对比：同一比赛里，基于 TF-IDF 稀疏特征 + Ridge 或浅层 MLP 的方案也很强。神经网络的优势在于自动学习词和品牌的表示，代价是训练更慢、调参更多。

05课堂讨论

  1. 品牌被 LabelEncoder 编成 0、1、2……的整数。如果直接把这个整数当数值喂给全连接层会有什么问题？Embedding 是怎么解决的？
  2. 标题只保留 10 个词、描述只保留 75 个词。pad_sequences 默认从前面截断，也就是丢掉开头保留结尾。对商品描述来说，这样合理吗？
  3. Tokenizer 只用训练集的文本建词表。测试集里出现训练集没见过的新词（比如新款手机型号），会被怎样处理？对定价有什么影响？
  4. 批大小 20000、只训练 5 轮。作者自己建议“减小批大小”。批大小对训练速度和最终效果各有什么影响？
  5. 第 16 格把 exp 还原写成了 +1 而不是 −1。这种“前后变换不对称”的错误为什么很难发现？你会怎样写代码来避免？
