动手试试 · 滞后特征、验证方式与递归预测 浏览器内模拟

浏览器生成 30 件商品各 400 天的模拟销量，按作者的方式造滞后、滚动均值和星期特征，把所有商品放进一张长表，现场训练一个梯度提升树（简化版 LightGBM，用平方误差而不是泊松目标），再对最后 28 天逐日递归预测。看看三件事：随机抽的验证集是否过于乐观；递归时误差会不会累积；只用 lag_28 时为什么不需要递归。

逐日递归预测 28 天，预测值乘上 1.028 / 1.023 / 1.018 三个系数后取平均（注释称来自 kyakovlev 的“魔法乘数”）第 25 格

训练日志里的 RMSE 和排行榜分数都不在下载的源码里，作者的文字也没写具体得分，所以这里不列分数。“0.50”是作者写在标题里的目标，不是本页验证过的结果。

这套方法能用在哪

  • 能预测：同时给成千上万件商品预测未来 28 天的日销量，一个模型搞定，不需要每条序列单独建模。
  • 同类问题：电商 SKU 销量、外卖门店订单量、共享单车各站点借还量、各地区用电量。凡是“很多条相似序列”的问题，都可以把它们摊成一张长表，用树模型统一学习。
  • 可迁移的套路：melt 成长表 → groupby(id).shift 造滞后 → 在滞后列上做 rolling → 日期与类别特征 → 树模型 → 逐日递归预测（或者只用 ≥ 预测步长的滞后，避免递归）。
  • 注意：滞后特征必须 groupby(id) 再 shift，否则会把上一件商品的销量“串”到下一件商品头上。

方法清单

  • 类别转整数编码、float32 / int16 省内存 第 5 格 第 8 格

05课堂讨论

  1. 作者的验证集是随机抽的行。同一件商品“昨天”在训练集、“今天”在验证集，会让验证分数偏乐观还是偏悲观？应该怎么切？
  2. 如果只用 lag_28（以及在它上面的滚动均值），预测未来 28 天时还需要逐日递归吗？那为什么作者还要加 lag_7？
  3. 销量是非负整数，大量为 0。为什么用泊松目标比用均方误差更合适？
  4. 预测值统一乘 1.02 左右的“魔法系数”能提分，说明模型的预测整体偏高还是偏低？这种做法有什么风险？
  5. 把 3 万条序列放进一个模型里，相比每条序列单独拟合一个 ARIMA，好处和坏处各是什么？
