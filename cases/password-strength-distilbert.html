01一分钟看懂

数据是什么

一列密码，一列强度等级

来自 Sber 举办的编程比赛（“Beauty Contest of the code from Sber”），任务是把密码分成 3 个强度等级。数据只有两列：密码字符串和它的强度类别。出处

要预测什么

强度 0、1、2

0 = 不可靠的密码，2 = 非常可靠的密码，1 在中间。出处 这是一个三分类问题。

用了什么方法

把密码当成一句“话”交给 DistilBERT

用 KerasNLP 加载预训练的 DistilBERT，接一个 3 类输出头；一共训练 3 个这样的模型，把它们的输出取平均再选最大的一类。出处出处

这套方法能用在哪

  • 能预测：用户注册时输入一个新密码，模型给出“弱 / 中 / 强”，在页面上提示用户换一个更结实的。
  • 同类问题：识别可疑用户名、判断短信或网址是不是钓鱼、给验证码难度分级。共同点是“很短的一串字符”。
  • 可迁移的套路：短文本也可以直接交给预训练语言模型 → 换一个分类头 → 多训练几个取平均。
  • 防御上的提醒：真实系统里，密码强度提示要在用户自己的设备上算，不能把明文密码发到服务器去“打分”。

方法清单

  • 数据整理：改列名、加长度列 第 11 格

05课堂讨论

  1. “Password”和“pASSWORD”在 uncased 模型眼里一模一样。你觉得这会让模型把哪一类密码判错？换成区分大小写的模型或字符级模型会怎样？
  2. 三个模型用的是同一个预训练起点、同一份数据、同样的设置。它们犯的错会不会高度相似？这样的“集成”还能带来多少提升？
  3. 第 33 格用加权平均算召回率。可以证明“加权召回率”一定等于准确率，为什么？这说明多打印一个指标不一定多一份信息。
  4. 数据集里的强度标签是怎么来的，notebook 没说。如果标签本身是某个规则程序打的，模型学到的是“密码真的难不难猜”，还是“那个程序的打分规则”？
  5. 做密码强度检测时，为什么不能把用户输入的明文密码发到服务器或者交给在线 AI 去判断？
