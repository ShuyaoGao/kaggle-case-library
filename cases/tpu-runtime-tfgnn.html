02数据长什么样

读代码时值得注意的地方

  • 只训练 1 轮：第 41 格写了早停逻辑（5 轮不涨就停），但 epochs = 1，早停实际不会触发。这是入门示例，真正比赛要多训练。
  • 配置特征乘以 100（第 37 格）：没有解释的经验常数，相当于手动放大配置特征的影响。
  • 几处未完成的文字：第 3 格的 GitHub 链接是空的，第 9 格说明只写了半句，第 18 格提到的 CONFIGS_PER_GRAPH_PER_EPOCH 和代码里的 CONFIGS_PER_GRAPH 名字不一致，Tile 部分没有写。
  • “连续编号保留”是简化做法：作者自己说分段 dropout 只保留编号连续的节点，欢迎改进（第 23 格；实验 A）。

这套方法能用在哪

  • 能预测：不用真的在芯片上跑，就能估计哪种编译配置更快，帮编译器自动挑选，省下大量试跑时间。
  • 同类问题：数据库查询计划选择、芯片电路布局、程序性能预测、云计算资源调度：对象本身是一张图，要在多个方案里挑最好的。
  • 可迁移的套路：把“方案”作为节点上的额外特征 → 同一张图对每个方案各算一个分数 → 用排序损失只学相对顺序 → 用成对排序准确率评估。

05课堂讨论

  1. 为什么这个比赛只要求“排对顺序”，而不要求预测准确的运行时间？对编译器来说，哪种信息更有用？
  2. 计算图本来是有方向的（数据从前往后流），作者却用 A + Aᵀ 把它变成无向的。这样做得到了什么、又丢掉了什么？
  3. 一张大模型的计算图可能有上万个节点。分段 dropout 只拿一段节点来训练，会不会漏掉远处节点之间的关系？
  4. OPA 只看“两两比较对不对”。如果最快的那个配置排错了，但其他都排对了，OPA 还会很高吗？编译器会满意吗？
  5. CNN 处理的图片大小固定、RNN 处理的是一条序列。为什么 AI 模型的计算图不能直接用 CNN 或 RNN 处理？
