读代码发现的问题：
① 第一版训练循环用的是 dataloader，但这个变量只出现在第 9 格的 Markdown 说明里，真正的代码里叫 train_loader 第 26 格；因为 EPOCH = 0 循环不执行，所以没报错。
② 生成器最后是 tanh，输出在 −1 到 1 之间，而 save_image 默认把像素当成 0 到 1，负值会被截成 0，交上去的图会偏暗 第 41 格（应加 normalize=True 或先做 (x+1)/2）。imshow 显示时也一样 第 35 格。
③ 评分代码里真图路径写成 ../all-dogs/all-dogs/，少了 input 一层 第 52 格，这可能是它跑不通的原因之一。
④ 第 14 格定义的权重初始化只用在了旧版 G/D 上，正式训练的新结构没有调用 第 31 格。

这套方法能用在哪

  • 能做什么：从随机数生成新图片；同一套“对抗”思想能做超分辨率、照片修复、风格转换、数据增强（作者在第 1 格也列了这些用途）。
  • 同类问题：生成人脸、动漫头像、医学影像扩充、合成训练数据。
  • 可迁移的套路：数据清洗与增强 → 生成器（转置卷积放大）+ 判别器（卷积缩小）→ 轮流训练、标签平滑、两边学习率分开调 → 固定噪声定期看图 → 用 FID 类指标评估。
  • 要警惕的：同样的技术能做“深度伪造”。识别伪造图片、给生成内容加标识，是同样重要的研究方向。

方法清单

  • 数据增强：Resize/CenterCrop 64、随机水平翻转、ColorJitter、±20° 旋转，归一化到 [−1, 1] 第 11 格
  • 初始化：卷积权重 N(0, 0.02) 第 14 格
  • 生成器：转置卷积 128 → 1024 → 512 → 256 → 128 → 64 → 3，tanh 第 20 格
  • 判别器：卷积 3 → 32 → 64 → 128 → 256 → 1，LeakyReLU，sigmoid 第 20 格
  • 训练：BCE 损失，Adam（G 0.0005、D 0.0003，β₁ = 0.5），真标签 0.95，200 轮 第 29 格 第 37 格
  • 评估：MiFID（Inception 特征 + 记忆距离）第 49 格

05课堂讨论

  1. 判别器如果太强（一眼就看穿所有假图），生成器还学得到东西吗？作者给 D 的学习率比 G 小，是在防什么？
  2. 真图的标签用 0.95 而不是 1（标签平滑）。这像是在提醒判别器什么？
  3. 数据里有“一张图三只狗”“狗和人合影”“杂志封面”。如果你来准备数据，会怎么清洗？代价是什么？
  4. 比赛规定不能交“改过的训练图”，所以评分要惩罚和训练图太像的结果。怎么判断一张生成图是“学会了”还是“背下来了”？
  5. 能画出以假乱真图片的技术，可能被怎样滥用？作为普通人，怎么判断一张网上的照片是不是生成的？
